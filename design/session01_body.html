Part A

The CIA triad

Security protects three things about your data: keep it private, keep it correct, keep it reachable. Think of your bank account.

Confidentiality — only you see your balance. Broken by data theft.
Integrity — your balance shows the right number. Broken by tampering.
Availability — the ATM works when you need it. Broken by DoS or ransomware.
Remember
Every attack you will ever triage breaks at least one of these three. Name the pillar first — it tells you how bad it is.
Part A

The four words analysts use every day

A vulnerability is a weakness (a broken lock). A threat is who might use it (a burglar nearby). An exploit is the actual break-in. Risk is the harm when it works. Weakness plus a motivated attacker plus a working exploit equals risk.

Attacker view
Attackers use malware to do the work: a virus or worm spreads, a trojan hides in something you trust, a RAT gives remote control, a keylogger steals what you type, and ransomware encrypts your files for money. The people behind it range from bored script kiddies to paid criminal crews and nation-state teams. Most attacks still start with one person clicking one thing — urgency, authority and curiosity are the levers they pull.
Analyst view
A Security Operations Centre (SOC) is the room that watches an organisation 24/7. Its whole job is to protect the CIA of the data: watch who opens sensitive files, catch changes that should not happen, and keep services online. You are training for the Tier 1 seat where alerts land first.

Part B

Inside Windows

Windows runs almost every corporate desktop, so it is where most alerts come from. You do not need to know every part — you need to know what normal looks like, so abnormal jumps out.

Your programs run in user mode. The kernel and drivers run below, in kernel mode, talking to the hardware through the HAL. Malware wants to move down this stack — the lower it gets, the harder it is to see and remove.

Places to know
C:\Windows\System32 holds the core system files — a fake file with a near-identical name hides well here. C:\Users\<you>\AppData is hidden by default and is a favourite drop spot. The Registry (HKLM, HKCU) is the settings database malware writes to for persistence.
Part B

Processes and the process tree

Every program that runs is a process, and each process is started by another one — its parent. Drawn out, this is the process tree. Attackers hide inside trusted names, so the shape of the tree gives them away.

Red flag
  • Office app starting a shell: WINWORD.EXE → powershell.exe
  • A program running from AppData\Temp or C:\Users\Public
  • No company name / unsigned, with a name close to a real one (svch0st.exe)
  • A PowerShell command line full of Base64 (-enc) or -w hidden
Analyst view
Four checks on any process, always in this order: path → signature → command line → parent. Process Explorer shows all four in one window.
Part B

Persistence — how malware survives a reboot

Attackers do not want to run once; they want to run every time the machine starts. They plant themselves in a handful of known places. One tool, Autoruns, checks all of them.

Attacker view
The easiest win is a Run key or the Startup folder — no admin needed. With admin they prefer a service or a scheduled task dressed as an update.
Red flag
An auto-start entry with no publisher, pointing to Temp, Public or a missing file.
Part B

What the SOC actually sees

Evidence — Windows Security log — Event ID 4688 — T1059.001
4688 New Process  |  Account: DGS\j.hassan  |  Host: DGS-WS01 (10.10.10.21)
New Process: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
Parent Process: C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE
Command Line: powershell -nop -w hidden -enc SQBFAFgAKABJAFcAUgApAA==
Analyst view
A Word document started a hidden, encoded PowerShell command. That is not something a document should ever do. This is the classic macro-to-PowerShell start of an attack — raise it, do not close it.

Lab B — in class · normal vs suspicious process
  1. Open Process Explorer as administrator and find the process tree.
  2. Pick any process. Check four things: path, company / signature, command line, parent.
  3. Right-click → Properties. Look at the Image and TCP/IP tabs.

Challenge — first triage

put it together
The scenario
An alert fires on DGS-WS01. A user opened an email attachment named invoice.docx. Minutes later the SOC sees this on the host:
  • Process tree: WINWORD.EXE → powershell.exe → cmd.exe
  • Event 4688: powershell.exe with a long -enc command line
  • Autoruns: a new unsigned entry update.exe in C:\Users\Public
  • Event 4720: a new local account svc-helper
Your job: which CIA pillars are at risk? Which ATT&CK techniques do you see? What do you do next, and would you close this or escalate it?
Show a model answer

CIA: Confidentiality and Integrity at risk (remote control + a new account); Availability could follow if it turns to ransomware.
Technique chain: phishing (T1566.001) → PowerShell execution (T1059.001) → persistence via the Public-folder entry (T1547) → new account (T1136.001).
Next steps: do not close it. Isolate the host, capture the running processes and network connections (Process Explorer, TCPView), collect the 4688/4720 events, and escalate — this is a live intrusion, not noise. Write findings (what you saw) separately from your conclusion (what it means).

Check yourself

answers hidden — try first
1. Which part of the CIA triad does ransomware attack most directly? Availability — it makes your files unusable until you pay. It can hit Integrity too.
2. A burglar is nearby and your lock is broken. Which is the threat and which is the vulnerability? The burglar is the threat; the broken lock is the vulnerability. The break-in is the exploit.
3. You see WINWORD.EXE → powershell.exe. Why is that suspicious? A document should not launch a shell. It is the classic macro-to-PowerShell start of an attack (T1059.001).
4. Which Event ID tells you a new process was created? 4688 — it also shows the parent process, which lets you rebuild the tree.
5. Many 4625 events in a short time suggest what? Repeated failed logons — password guessing or a brute-force attempt.
6. Which tool shows you all the places malware can auto-start? Autoruns (Sysinternals) — it checks Run keys, Startup, Scheduled Tasks, Services, drivers and more.
7. A program runs from C:\Users\Public\update.exe with no publisher. Verdict? Suspicious — odd location plus unsigned. Investigate the command line, parent and network before deciding.
8. What does whoami /priv show, and why care? Your account's privileges. Powerful ones (like SeDebugPrivilege) let an attacker dump credentials.
9. Event 4720 followed by 4672 — what story does that tell? A new account was created and then used with admin rights — a likely backdoor. Escalate.
10. Why keep findings and interpretation separate in your notes? So others can trust the facts and check your reasoning. Facts first (the log line), conclusion second.
Practical 1 — on DGS-WS01 Open Event Viewer → Security. Find one 4624 and one 4688 event. Write down the account, the logon type, and (for 4688) the parent process.
Practical 2 — on DGS-WS01 In Process Explorer, find a process running from a user folder. Record its path, publisher, command line and parent, then give a one-line verdict with your reason.

Key takeaways

Remember
  • Every attack breaks a CIA pillar — name it first.
  • Vulnerability → threat → exploit → risk.
  • The shape of the process tree gives attackers away: path, signature, command line, parent.
  • Persistence lives in a few known places — Autoruns sees them all.
  • Six Event IDs: 4624 · 4625 · 4672 · 4688 · 4720 · 7045.
  • Every attack has a detection and an ATT&CK ID. Findings first, conclusion second.
